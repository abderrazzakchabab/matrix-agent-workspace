## Backend sharp edges

- **RLS tenant context:** the app connects as `matrix_app` (subject to RLS); migrations/fixtures connect as the table-owner `matrix`. Policies key on the `app.user_id`/`app.workspace_ids` GUCs. Custom GUCs revert to an empty string after a `SET LOCAL` commit, so policies must read them via the `app_user_id()`/`app_workspace_ids()` NULLIF helpers defined in `apps/control-plane/src/db/migrations/0001_identity_and_bindings.sql`.
- **Synapse fixture** (`infra/docker-compose.test.yml`): the image drops to uid 991 via gosu, so writable state lives under `infra/synapse/runtime/` (git-ignored) and is chowned by the entrypoint; the signing key is generated at startup, never committed. Login/join/message/room-creation rate limits are relaxed in `infra/synapse/homeserver.yaml` for integration and end-to-end fixture seeding.
- **Integration fixtures:** common start, health, Phase B/A gate, and teardown commands plus seeded identities are documented in `README.md`. Vitest resets shared tables and uses `fileParallelism: false` to avoid cross-file interference.
- **Migrations are auto-discovered:** `runMigrations()` in `apps/control-plane/src/db/client.ts` applies every `migrations/*.sql` file in sorted order, so new migrations need no registration. Apply via the owner role (`MIGRATIONS_DATABASE_URL`); the app role (`DATABASE_URL`) stays RLS-bound.
- **Phase C write controls** (`src/github/write-authorization.ts`, `approval-service.ts`, `mutation-command.ts`, `mutation-worker.ts`): read access never implies write access — `enqueueMutationCommand` checks grant (repository+scope, `WRITE_SCOPE_REQUIRED`), then the exact unexpired approval (workspace/run/user/scope/command hash, `APPROVAL_*`), then inserts the command with `INSERT ... ON CONFLICT (workspace_id, idempotency_key) DO NOTHING` and re-selects for replays. The worker re-checks both gates immediately before the provider call, persists `provider_result` BEFORE `status='completed'` (crash recovery never re-mutates), and records append-only `audit_records` (INSERT+SELECT grants only; payloads stored as `[REDACTED]`). Worker tenant resolution uses the SECURITY DEFINER helper `mutation_command_tenant(id)` (same pattern as `pending_matrix_delivery_tenants`) before re-entering `withTenant` as the command owner.
- **Envelope encryption** (`apps/control-plane/src/security/envelope-encryption.ts`) is AES-256-GCM. `ENVELOPE_KEY_HEX` is a comma-separated `version:hex` list (each key 32 bytes hex) and `ENVELOPE_KEY_VERSION` picks the active key; `decryptAndReencrypt` rotates old versions on access. Never persist plaintext tokens.
- **SECURITY DEFINER boundaries:** tenant-scoped helpers run as the table owner and bypass RLS, so `append_run_event` (per-run sequence, locks the run row for contiguous sequences) and `update_checkpoint` explicitly re-assert `app_workspace_ids()` membership before writing. The global sweeper helper `pending_matrix_delivery_tenants` exposes only run-owner/workspace IDs; payload and token access happens after the worker re-enters `withTenant` as that owner.
- **Durable runs** (`apps/control-plane/src/workflows/run-workflow.ts`): `executeRun` is the pure orchestration core over injectable services (provider/checkpoints/runStore/events/cancellation); the Inngest function (`inngest/functions/run-requested.ts`) wires the Postgres implementations. Checkpoints (`specialist:<id>`, `workflow:init/done/injection`) are the resume authority — completed specialists are never rerun. Terminal transitions go through `WorkflowRunStore.finalize` (guarded UPDATE ... NOT IN terminal), which makes the single terminal event exactly-once. Deterministic execution key = sha256(runId, promptHash, canonical config hash); a resume with a different key fails with `EXECUTION_KEY_MISMATCH`.
- **Specialist config** (`agents/agent-config.ts`): profiles pin model/gateway provider/timeout/limits; `toolsAllowlist` must be a subset of `READ_ONLY_TOOL_ALLOWLIST` — validation rejects anything else, `GITHUB_MUTATION_TOOLS` is empty, and provider tools are derived only from the validated profile, never from prompt text. Prompt envelopes (`agents/prompt-envelope.ts`) wrap untrusted spans in `<untrusted-data source=... source-id=...>` delimiters; the injection detector applies `promptInjectionMode` (`exclude_span` | `fail_run`, default `fail_run`).
- **Event stream + Matrix delivery** (`events/event-service.ts`, `matrix/delivery-worker.ts`): event-producing routes and workflows append `run_events` and enqueue `outbox_messages` in one transaction, keyed `delivery_key = runId:sequence:roomId`; terminal workflow transitions atomically persist status, event, and outbox. The SSE route replays/streams `run_events` only; the worker consumes the outbox under the run owner's `withTenant` context. The delivery key is the Matrix txnId, so retried 5xx/429 sends are idempotent, and delivery failure never touches run status.
- **Test seams:** hermetic workflow/agent tests use the in-memory stores exported from `workflows/*` plus the `DeterministicProvider` fixture in `test/workflows/support.ts` (records every call, including failed attempts — retry assertions depend on that). `test/api/run-launch.test.ts` needs the postgres+synapse compose fixtures and spies on `dispatchRunRequested` via `vi.mock` of `inngest/client`. `pnpm lint` is `tsc --noEmit`; route handlers must pass `NextRequest` (not `Request`) into `auth/authorization.requireSession`.
- **Phase A mobile gate** (`apps/mobile/test/e2e/phase-a-mobile.spec.ts` + `apps/control-plane/test/e2e/phase-a-mobile-fixture.ts`): Playwright starts the control plane and Expo web itself (`playwright.config.ts` `webServer`; `apps/mobile/app.json` sets `web.output: "single"`). The fixture owns a module-level admin `Pool` on `MIGRATIONS_DATABASE_URL` that is a singleton for the whole Playwright process — never end it in a spec teardown (`closePhaseAMobileDatabase` is standalone-only). Its `beforeAll` replays every migration and truncates `rooms`/`users`, so `assertIsolatedTestDatabase()` requires one dedicated `*_test` database reachable by both the app and owner roles. `PHASE_A_FIXTURE_MODE=1` turns on test-only wiring — browser-cookie sessions, the `__phaseAMobileTest.forceSseDisconnect` hook, and control-plane CORS headers — all inert in production builds.

- **Phase C mobile workspace** (`apps/mobile/src/screens/GitHubWorkspaceScreen.tsx` + `components/GitHubReadPanel|MutationConfirmation|AuditHistory`): reached from the Run screen header (`GitHubWorkspace` route) with `workspaceId`/`runId` from navigator state; the installation id comes from `EXPO_PUBLIC_GITHUB_INSTALLATION_ID` (no list-installations endpoint exists; `playwright.config.ts` injects fixture value `42` into the Expo webServer env). The client recomputes the server command hash (canonical JSON key sort + SHA-256 via expo-crypto) and retries reuse the same idempotency key per argument fingerprint. Fixture sharp edges: the wiremock issues page 2 advertises a dangling `next` link and page 3 404s, so cursor-following clients must treat a failed follow-up page as end-of-pagination; the Task 12 mobile e2e (`test/screens/github-workspace.e2e.tsx`) stays outside the committed `playwright.config.ts` `testMatch` (`*.spec.ts`) — the committed mobile gate is `test/e2e/phase-c-workspace.spec.ts`; mobile-imported fixture helpers must stay free of control-plane `src/` imports (the mobile `tsc` program type-checks them and fails on `process.env`-any constructs).
- **Phase C e2e gate (Task 13)** (`apps/control-plane/test/e2e/phase-c-github-writes.spec.ts`, `apps/mobile/test/e2e/phase-c-workspace.spec.ts`): `specialist_agents.id` is globally unique and `SPECIALIST_REGISTRY` resolves canonical profile ids, so a spec file seeds exactly one workspace (each file's `beforeAll` truncates first; files run serially). The deterministic worker-crash control is `PHASE_C_FIXTURE_MODE=1` + an idempotency key containing `[fixture:crash-after-provider]` (mutations route wraps `markCompleted` to throw once per key per server process); the replay path in `enqueueMutationCommand` finalizes a queued command with a persisted `provider_result` via the worker instead of re-calling the provider. `CONTROL_PLANE_URL` for browser specs must keep the `localhost` hostname (the Expo web origin is `localhost:19006`; `127.0.0.1` is cross-site and the `SameSite=Lax` session cookie is blocked on POST → 401s); when a foreign process squats :3000, run with `PORT=3100 CONTROL_PLANE_URL=http://localhost:3100` and `CONTROL_PLANE_PORT=3100 docker-compose ... up -d inngest` (compose interpolates `${CONTROL_PLANE_PORT:-3000}` into the Inngest `--sdk-url`).
